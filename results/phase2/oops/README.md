# OOPS! Results

Outputs from the [OOPS! Ontology Pitfall Scanner](https://oops.linkeddata.es/) applied to both generated ontologies.

OOPS! scans an OWL/RDF file for common modelling pitfalls. Each pitfall has a code (P04, P05, ...), a severity (Minor / Important / Critical), and a count of affected elements.

## Files

| File | Contents |
|---|---|
| `music_oops_report.txt` | Full OOPS! report for the music ontology — all pitfalls, severities, and affected element URIs |
| `hospital_oops_report.txt` | Full OOPS! report for the hospital ontology |
| `oops_summary.csv` | One row per pitfall code: severity, case count for music, case count for hospital |
| `oops_affected_elements.csv` | One row per affected element: domain, pitfall code, severity, element URI, note |

## Key findings

Both ontologies share the same structural pitfall profile. Pitfalls present in both:

| Code | Severity | What it means |
|---|---|---|
| P39 | Critical | No ontology URI declared — namespace resolves to file path |
| P05 | Critical | Declared inverse properties that are not logically inverse |
| P19 | Critical | Multiple rdfs:domain or rdfs:range on one property (interpreted as intersection in OWL) |
| P38 | Important | No owl:Ontology declaration — no metadata block at all |
| P41 | Important | No license declared |
| P24 | Important | Classes appear in their own definition (recursive) |
| P08 | Minor | No rdfs:label or rdfs:comment on most elements |
| P13 | Minor | Object properties without owl:inverseOf declared |
| P22 | Minor | Mixed naming conventions (CamelCase and underscore prefixes mixed) |
| P04 | Minor | Isolated classes with no relations to the rest of the ontology |

Music only: P35 (one untyped property `#hasPart`).
Hospital has more P24 cases (7 vs 3) and more P04 cases (3 vs 1).

These results are not generated by `scripts/phase2/evaluation_phase_II.py`.
The ontology files were submitted manually to the OOPS! web tool.
