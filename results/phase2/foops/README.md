# FOOPS! Results

Outputs from the [FOOPS! FAIR Ontology Assessment tool](https://foops.linkeddata.es/) applied to both generated ontologies.

FOOPS! checks how well an ontology conforms to the FAIR principles (Findable, Accessible, Interoperable, Reusable). Each check has a code (PURL1, RDF1, OM1, ...) and a pass/fail score (0% or 100%).

## Files

| File | Contents |
|---|---|
| `music_foops_report.txt` | Full FOOPS! report for the music ontology — all checks with explanations |
| `hospital_foops_report.txt` | Full FOOPS! report for the hospital ontology |
| `foops_summary.csv` | One row per check: FAIR principle, description, score for music, score for hospital |

## Key findings

Both ontologies score identically: **2 of 15 checks pass (13%)**.

Passing checks (both ontologies):
- **RDF1** (I1): Ontology is available in valid RDF — the TTL files parse correctly.
- **VOC2** (I2): Ontology reuses/extends existing vocabularies (terms from their own namespace are used consistently).

All other checks fail because the generated ontologies contain no metadata: no `owl:Ontology` declaration, no title, no license, no creator, no version IRI, no namespace prefix, no `rdfs:label` or `rdfs:comment` on any term.

The Accessible category ran no checks because the ontologies were submitted as local files rather than by public URI.

Note: the 0% scores on VOC3 and VOC4 ("No ontology terms found") are a FOOPS! parsing artefact — the tool could not identify typed terms when no owl:Ontology block is present, even though the ontologies contain many classes and properties (confirmed by OOPS! results and basic statistics outputs).

These results are not generated by `scripts/phase2/evaluation_phase_II.py`.
The ontology files were submitted manually to the FOOPS! web tool.
